# meshi web frontend ページ設計

meshi の web frontend のページ構成を定義する。
UI デザイン作成の入力となる、画面一覧とその構成要素、レスポンシブ方針をまとめたもの。

## プロダクト前提

- meshi は個人用の食事管理サービス。
  利用者は 1 人だけで、認証やマルチユーザーの概念はない。
- 食事の登録は当面 Slack (チャット) がメインで、web は「閲覧と振り返り」が主用途。
  ただし将来は web での直接登録がメインになる可能性があるため、登録導線は全画面に常設し、登録が主役に昇格しても画面構成が変わらないようにする。
- モバイルとデスクトップの両対応 (レスポンシブ)。
  モバイルは下部タブバー + FAB、デスクトップは左サイドバー + 常設の登録ボタン。

## データモデル前提 (デザインに影響するものだけ)

- 食事記録は 1 レコード = 1 品目。
  各レコードは食品名、量と単位 (「300 g」「1 杯」のような自由単位)、食べた日時、メモを持つ。
  複数品目をまとめる「1 回の食事」というエンティティは存在しない。
- 各レコードは**食事区分 (朝食 / 昼食 / 夕食 / 間食)** を持つ。
  区分カラムは現行スキーマに無く、この frontend と併せて追加する。
  登録時の既定値は食べた時刻から推定する (04:00–10:59 朝食、11:00–15:59 昼食、16:00–22:59 夕食、それ以外 間食) が、利用者が変更できる。
- 栄養素は主要 6 種 (エネルギー kcal、たんぱく質、脂質、炭水化物、食物繊維、食塩相当量) と、ビタミン/ミネラルなど 17 種。
  表示は主要 6 種を既定とし、残りは折りたたみで開く。
- 食品の栄養値には推定値フラグがある。
  推定値を含む品目や集計は、その旨を表示する必要がある。
- 栄養素ごとに日次目標値を設定できる (未設定の場合もある)。

## 画面一覧

| 画面          | パス           | 役割                                                |
| ------------- | -------------- | --------------------------------------------------- |
| 今日 (ホーム) | `/`            | 今日の食事と栄養バランス                            |
| 日別詳細      | `/days/:date`  | 任意の日の食事と栄養バランス (今日と同一レイアウト) |
| 履歴          | `/history`     | カレンダー / リスト / レポートの 3 ビュー           |
| 食品          | `/foods`       | 登録済み食品マスタの検索と一覧                      |
| 食品詳細      | `/foods/:id`   | 食品の栄養成分と喫食履歴                            |
| 設定          | `/settings`    | プロフィールと栄養目標                              |
| 登録シート    | (画面ではない) | 全画面から開くグローバルオーバーレイ                |

ナビゲーションは「今日」「履歴」「食品」「設定」の 4 項目。

## 各画面の構成

### 今日 (ホーム) `/`

上から順に:

1. **ヘッダー**: 今日の日付。前日へ戻るナビ (前日の日別詳細へ遷移)。
2. **栄養サマリ**: エネルギーが主役。
   摂取 kcal と目標 kcal、達成率をリングまたは大きなバーで表示する。
   その下にたんぱく質 / 脂質 / 炭水化物 / 食物繊維 / 食塩の摂取量 vs 目標のバー。
   目標未設定の栄養素は摂取量のみ表示し、目標が 1 つも無い場合は「目標を設定」への導線を出す。
   折りたたみで全栄養素のテーブルを開ける。
   集計に推定値が含まれる場合は「推定値を含む」の注記を添える。
3. **食事タイムライン**: 朝食 / 昼食 / 夕食 / 間食のグループ見出し (グループ小計 kcal 付き) の下に品目行を並べる。
   グループの並びは朝食 → 昼食 → 夕食 → 間食で固定し、グループ内は時刻順。
   品目行は食品名、量と単位、kcal、推定バッジ、メモ。
   記録の無いグループは表示しない。
   品目タップで登録シートを編集モードで開く。
4. **空状態**: 記録が 1 件も無い日は「今日の記録はまだありません」と登録ボタンを中央に表示。

### 日別詳細 `/days/:date`

今日ページと同一レイアウト。
差分はヘッダーのみで、前日 / 翌日ナビとカレンダー (履歴) へ戻る導線を持つ。

### 履歴 `/history`

ビュー切替タブでカレンダー / リスト / レポートを切り替える。

- **カレンダービュー**: 月表示。
  各日セルにはデスクトップでは kcal 合計、モバイルでは目標達成度を示す色ドットを表示する。
  日タップで日別詳細へ。月送りナビ付き。
- **リストビュー**: 日別カードを新しい順に並べる無限スクロール。
  カードは日付、kcal 合計、品目の要約 (先頭数品 + 残り件数)。
  タップで日別詳細へ。
- **レポートビュー**: 期間切替 (週 / 月) と期間送りナビ。
  内容は上から、期間内のエネルギー推移チャート (日次バー + 目標線)、主要栄養素の 1 日平均 vs 目標のバー、全栄養素の平均値テーブル (目標比付き)。
  「今週の栄養バランスはどうか」に答えるビュー。

### 食品 `/foods`

- 検索ボックス (あいまい検索)。
  未入力時は「最近食べた」「よく食べる」の 2 セクションを表示する。
- 食品リスト行: 名前、100 g あたり kcal、由来バッジ (Web 検索 / 成分表推定 / 手入力)、推定バッジ。

### 食品詳細 `/foods/:id`

- 栄養成分表 (100 g あたり)。主要 6 種を先頭に、折りたたみで全栄養素。
- 別名一覧、由来と出典リンク。
- 喫食履歴: この食品を食べた記録の一覧 (日時、量) と累計回数。

### 設定 `/settings`

- **プロフィール**: 好きな食べ物 / 嫌いな食べ物 / アレルギー / 制約 (自由記述) のタグ編集。
- **栄養目標**: 栄養素ごとの日次目標値の編集。
  主要 6 種を既定で行表示し、その他の栄養素は「追加」で行を増やす。

### 登録シート (グローバルオーバーレイ)

モバイルはボトムシート、デスクトップはモーダル。
全画面の FAB / 登録ボタンから開く。

フロー:

1. **食品検索**: 入力前は「最近食べた」「よく食べる」のサジェストを表示。
   入力するとあいまい検索の候補 (履歴優先のランク順) を表示する。
2. **品目選択**: 候補から選ぶ。
   マスタに無い場合は食品成分表由来の候補を「新規追加候補」として表示する。
   それも無い場合は v1 では Slack での登録を促す文言を出す (将来はここから自由入力をエージェントに渡す)。
3. **詳細入力**: 量と単位、食事区分 (既定は時刻から推定)、日時 (既定は現在時刻)、メモ。
4. **保存**: 保存後「続けてもう 1 品」ボタンで連続登録できる。

編集モードでは既存品目の量 / 食事区分 / 日時 / メモの変更と削除ができる。
削除は確認ダイアログを挟む。

## 横断ルール

- 栄養素の表示順は定義済みの表示順 (主要 6 種が先頭) に従う。
- 量は記録時の単位のまま表示する (g 換算などはしない)。
- 推定値は品目単位ではバッジ、集計値では注記で示す。
- 日付の境界は Asia/Tokyo 基準で扱う。
- ローディングはスケルトン表示、通信エラーは再試行ボタン付きのメッセージで統一する。

## スコープ外

- 認証、マルチユーザー対応。
- 食事レコメンド (「次に何を食べるべきか」) の UI。バックエンドには機能があるため将来候補。
- frontend 用 API の設計。現状バックエンドは MCP / A2A のみで REST が無いため別途設計するが、ページ設計には影響しない。
- 食事区分カラム追加の実装 (スキーマ変更と、Slack 経由の登録パイプラインでの区分付与)。この文書では前提としてのみ扱う。
